# 시안 라운드

말로 "조금 더 세련되게"를 몇 번 주고받는 것보다, 서로 **확실히 다른** 안을 여러 개 놓고 고르는 편이 빠르다. 이 사용자의 작업에서 반복된 흐름이다(교재 유형 박스 A~I안 → "I안에 G안의 세로선", 대표문제 7안, 표지 10안 → "6번으로").

## 언제 시안 라운드로 바꾸나
- 같은 대상에 디자인 지적이 **두 번** 이어졌다("AI틱해" → 고쳤는데 또 "안 되겠다").
- 사용자가 "시안", "여러 개", "N개 뽑아"라고 했다.
- 처음 만드는 시리즈의 대표 요소(표지, 제목 띠, 문제 박스)라 기준이 아직 없다.

## 순서
1. **고정할 것과 바꿀 것을 나눈다.** 모든 안에 똑같이 들어갈 것(문구, 로고, 판형, 이미 확정된 요소)을 먼저 적는다. 확정된 요소("유형박스는 3안 고정")는 절대 바꾸지 않는다.
2. **피할 것을 적는다.** 같은 계열의 기존 결과물(다른 시리즈 표지·양식)과 겹치는 특징을 찾아 목록으로 만든다. "AWAKE·CRACK과 겹치지 않게"면 그 두 표지의 바탕 무늬·구도·색을 직접 보고 적는다.
3. **방향이 다른 안을 만든다.** 기본 개수는 표지·큰 요소 6~10개, 작은 요소(박스·칩) 4~9개. 색만 바꾼 안은 한 안으로 친다. 안마다 축 하나를 크게 다르게: 구도(대칭·왼쪽 정렬·위아래 나눔·세로쓰기), 바탕(색면·종이·도형·무늬), 강조(굵은 선·큰 기호·띠·인장), 색(브랜드색 전면·어두운 바탕·흰 바탕).
4. **한 장에 모은다.** 같은 크기로 줄여 번호와 짧은 이름을 붙인 비교 그림 1장 + 안별 원본(PNG 또는 PDF 쪽). HTML 격자로 짜서 브라우저로 찍으면 빠르다.
5. **번호표로 보고한다.** `| 번호 | 이름 | 특징 |` 한 줄씩. 끝에 "한 개를 골라도 되고, '02 구성에 06 색'처럼 섞어도 됩니다."
6. **고른 뒤.** 고른 안과 섞을 요소를 그대로 반영한다. 고르지 않은 안은 `이전안_v1/`처럼 폴더로 옮기고 지우지 않는다. 확정은 `PROGRESS.md`의 확정된 결정과 프로젝트 문서(양식 규칙)에 적는다.

## AI틱함·촌스러움 점검표 (보내기 전에)
- 장식이 내용을 이기지 않는가: 의미 없는 삼각형·물결 무늬, 흰 카드에 그림자, 글자 사이를 크게 벌린 영문 부제("M A T H E M A T I C S"), 쓸모없는 메모 칸.
- 글꼴은 2종 이하. 크기 단계는 3~4개. 기존 시리즈가 있으면 **그 시리즈의 실제 pt·비율을 재서** 맞춘다(눈대중 금지).
- 흰 글씨를 밝은 색 바탕에 올리지 않는다. 로고가 바탕색에 묻히지 않는지 본다.
- 작은 로고 그림을 크게 키워 흐려지지 않았는가. 크게 쓸 로고는 벡터로 다시 그리고, 큰 판은 선을 굵게 만든다.
- 지정한 글꼴이 **실제로 들어갔는지** PDF 글꼴 목록으로 확인한다. Windows에서 사용자 글꼴은 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`에 있어 `C:\Windows\Fonts`만 보면 못 찾고 다른 글꼴로 바뀐다.

## 하지 않는 것
- 사용자가 고른 안을 "더 낫게" 임의로 바꾸지 않는다. 바꾸고 싶으면 별도 안으로 같이 보낸다.
- 시안 단계에서 최종 인쇄 파일까지 만들지 않는다. 고른 뒤에 만든다(`print-cover`).
