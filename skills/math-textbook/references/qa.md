# 단원 PDF 검수

보내기 전에 아래를 차례로 한다. 레이아웃 판단 기준은 `print-doc-qa` 스킬 표를 함께 쓴다.

## 1. 기계 점검
- [ ] 인디자인 점검 보고서: 끊어진·수정된 링크 0, 없는 글꼴 0, 넘친 글 0, 150ppi 미만 그림 확인. 원래부터 끊긴 템플릿 견본 링크는 이유를 적어 둔다.
- [ ] `python scripts/pdf_fonts.py 단원.pdf` — 수식 글꼴이 정해진 것뿐인지, 대체 글꼴(Times New Roman, 굴림)이 없는지.
- [ ] 쪽 수: 단원 쪽 수가 짝수이고(MEMO 포함), 다음 단원이 오른쪽 쪽에서 시작.
- [ ] 개수: 원고목록의 문항 수 = 문항번호표 줄 수 = PDF에 찍힌 번호 수. 스크립트로 센다.
- [ ] 정답: 빠른 정답 표의 답 수 = 문항 수, `?` 없음.
- [ ] 원형 쪽(조립용 견본 쪽)이 PDF에 들어가지 않았다.

## 2. 쪽 그림으로 보기
`scripts/pdf_render.ps1 -PDF 단원.pdf -DPI 120`으로 모든 쪽을 그림으로 뽑아 직접 본다. 의심 부분은 300~400dpi로 다시.

| 볼 것 | 기준 |
|---|---|
| 첫 쪽 | 단원 첫 쪽에 흰 바탕·바닥글·상자 선이 다른 쪽과 같다(마스터 배경 덮임 함정) |
| 머리 | 대단원·소단원 번호와 제목이 맞고, 긴 제목이 한 줄에 들어간다 |
| 번호 맞춤 | 번호와 문제 첫 줄의 높이 관계가 교재 규칙대로(윗선 맞춤 또는 가운데). 한 줄 문항은 가운데 |
| 줄 잇기 | 이은 줄의 글자 아랫선이 같다. 보기 칸이 고르다. 식 중간에서 끊기지 않는다 |
| 겹침 | 문항·그림·상자·바닥글·단원 탭이 서로 겹치지 않는다 |
| 풀이 칸 | 남는 높이가 문항 사이에 고르게 나뉘었고, 정해진 최소 높이 이상 |
| 수식 | 개념 수식과 문제 수식이 같은 모양·굵기·첨자 높이 |
| 흰 네모 | 캡쳐 흰 바탕이 색 바탕 위에 네모로 보이지 않는다(곱하기 혼합) |
| 글자 크기 | 같은 역할 글자가 쪽마다 같은 크기. 한 곳만 줄인 데가 없다 |

## 3. 보고
- PDF 경로, 쪽 범위(인쇄 쪽 번호), 쪽 구성(개념 n · 문항 n · MEMO n)
- '확인할 것': OCR로 읽은 제목, 직접 넣은 정답, 글씨를 줄인 쪽, 대체 글꼴, 자동 판단을 사람이 바꾼 곳
- 확인하지 못한 것은 "미확인"으로 적는다.

## 4. 고친 뒤
- 고친 쪽만이 아니라 뒤로 밀린 쪽까지 다시 그려 본다.
- 공용 코드를 고쳤으면 다른 교재의 같은 쪽 종류도 하나 뽑아 본다.
