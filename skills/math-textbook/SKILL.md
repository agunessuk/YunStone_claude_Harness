# 수학 교재 제작 공통 기술 (인디자인 + PDF)

교재 한 권의 고유 양식이 아니라, **어떤 교재를 만들든 똑같이 반복되는 원리·함정·검사**만 담았다.
근거: 시리즈 5종(개념서·유형서·심화·학습지 변형)을 인디자인 자동화로 만들며 확정한 하네스에서 교재와 무관한 부분만 뽑았다.

## 먼저 정할 것
- 프로젝트에 교재별 규칙(CLAUDE.md, 시리즈 스킬, 레이아웃 숫자표)이 있으면 **그것이 우선**이다. 이 스킬은 빈 곳을 채우는 기본기다.
- 템플릿 indd와 받은 원본 PDF는 **읽기 전용**. 작업은 복사한 작업본에서만 한다.
- 인디자인 자동화는 사용자가 요청할 때만. 몇 분 걸리는 조립·PDF는 백그라운드로 돌린다.

## 핵심 원칙 6가지
1. **캡쳐를 그대로 붙이지 않는다.** 머리·제목·번호·상자 같은 템플릿 요소는 템플릿 양식으로 새로 쓰고, 외부 자료는 필요한 부분만 잘라 다시 짠다.
2. **벡터 그대로.** 문제지 PDF는 PNG로 바꾸지 말고 PDF의 한 영역(쪽·x·y·폭·높이, pt)을 인디자인에 벡터로 앉힌다. PNG는 미리보기·분석용으로만 쓴다.
3. **숫자는 표, 모양은 코드.** 칸 폭·글씨 배율·간격 같은 숫자는 CSV 한 곳(레이아웃 표)에 두고, 피드백이 숫자면 표만 고쳐 다시 뽑는다.
4. **단원 단위로 다시 뽑을 수 있게.** 조립한 쪽마다 레이블(`단원·종류`)을 붙여, 같은 단원을 다시 조립하면 그 단원 쪽만 지우고 새로 만든다.
5. **글자 크기 통일.** 줄바꿈 때문에 한 곳만 글자를 줄이지 않는다. 줄여야 하면 같은 역할 전체를 함께 줄인다.
6. **직접 보고 보낸다.** PDF를 쪽 그림으로 그려 겹침·넘침·줄바꿈을 보고, PDF에 든 수식 글꼴 목록을 확인한 뒤 보낸다(`print-doc-qa` 스킬과 함께).

## 한 단원이 만들어지는 흐름
| 단계 | 하는 일 | 자세히 |
|---|---|---|
| 1. 자료 등록 | 개념 PDF·문제지 PDF를 단원 폴더에 **복사**(원본 유지) | [pipeline.md](references/pipeline.md) |
| 2. 자르기 | 문제지를 문항·해설·정답으로 나누고 영역(pt)을 CSV에 | [pdf-source.md](references/pdf-source.md) |
| 3. 줄 잇기 | 좁은 단의 줄을 교재 칸 폭에 맞게 다시 채운 조각 목록 | [pdf-source.md](references/pdf-source.md) |
| 4. 원고 | 문항 순서·묶음·정답·출처를 원고 CSV로. 개념은 옮겨 적은 원고(.txt) | [pipeline.md](references/pipeline.md) |
| 5. 조립 | 작업본에 원형 쪽을 복제해 단원 쪽을 만들고 문항을 벡터로 앉힘 | [indesign-automation.md](references/indesign-automation.md) |
| 6. 수식 | 개념·풀이의 수식을 KaTeX 글꼴로 조판 | [math-typesetting.md](references/math-typesetting.md) |
| 7. PDF·검수 | 단원 PDF → 쪽 그림 확인 → 글꼴 확인 → 사용자 확인 → 다음 단원 | [qa.md](references/qa.md) |

## 스크립트 (`scripts/`, 추가 설치 없음)
| 파일 | 하는 일 |
|---|---|
| `pdf_fonts.py <PDF> [--family KaTeX_ --allow 이름…] [--forbid 글자…]` | PDF에 박힌 글꼴 목록. `--family`로 시작하는 글꼴이 `--allow`에 없거나 `--forbid` 글자가 든 글꼴이 있으면 실패(끝 코드 1). 수식 글꼴 확인용 |
| `jsx_lint.py <파일·폴더> [--ps1] [--quiet]` | `.jsx`·`.jsxinc`의 ES3 함정(let/const, 화살표 함수, 템플릿 문자열, JSON, 배열 고차 함수 등)과 UTF-8 BOM 누락, 문자열 속 수식 기호(→ `String.fromCharCode`) 검사 |
| `pdf_render.ps1 -Pdf <경로> [-Dpi 150] [-Pages "1-3,8"] [-OutDir …] [-Ocr]` | 윈도우 내장 PDF 렌더러로 쪽을 PNG로. `-Ocr`이면 윈도우 한국어 OCR 낱말 좌표 CSV도 |
| `indesign_run.ps1 -Jsx <파일> \| -Code <코드> [-Doc <작업본>] [-Options "{unit:'01'}"] [-Protect 템플릿보관소] [-Save]` | 인디자인을 COM으로 열어 JSX를 대화상자 없이 실행하고 결과 글을 돌려줌. JSX 안에서 `$.global.TEST`·`TEST_OPTIONS`·`TEST_LOG` 사용 |

수식 글꼴 확인 예: `python scripts/pdf_fonts.py 단원.pdf --family KaTeX_ --allow KaTeX_Main-Regular KaTeX_Math-Italic KaTeX_Size1-Regular --forbid TimesNewRoman`

PowerShell 스크립트는 `powershell -NoProfile -ExecutionPolicy Bypass -File <스크립트> …`로 실행한다. 매개변수에 배열을 넘기지 말고 쉼표 글자 하나로 넘긴다.

## 피드백 받았을 때
- 규칙 하나로 바꾼다: 숫자면 레이아웃 표, 모양이면 코드. 그 단원을 다시 조립하고 **바뀐 쪽을 그림으로** 확인한 뒤 보낸다.
- 공용 코드(조판 엔진·조립 공통부)를 고쳤으면 그 코드를 쓰는 다른 교재도 영향받는다고 알린다.
- 같은 지적이 두 번 나오면 프로젝트 품질 기준에 규칙으로 올린다(`feedback-round`).

## 하지 않는 것
- 템플릿 원본을 열거나 복사해서 구조를 보지 않는다. 작업본의 사본을 연다.
- 인디자인 화면을 클릭으로 조작하지 않는다. COM + JSX로만.
- 사용자가 인디자인에서 손으로 고친 단원을 말없이 다시 조립하지 않는다(손질이 사라짐 — 먼저 알린다).
- 교재별 양식(시리즈 이름, 쪽 구성, 색, 문구)을 이 스킬에 적지 않는다. 그 프로젝트의 문서에 적는다.
