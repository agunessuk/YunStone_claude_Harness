# 몹 모델 스타일 맞추기·디테일 살리기 (ModelEngine)

흐름: **검사 → 라인업으로 차이 보기 → 처방 고르기 → (밀도 맞추기) → (다시 칠하기) → (부품 보강) → 다시 검사·라인업·동작 확인 → 사람 승인**.
모든 단계가 스크립트라 같은 입력에서 같은 결과가 나오고, 원본은 읽기만 한다. 결과는 `작업/모델링/모델/` 복사본.

## 준비
- 스크립트: 이 스킬의 `scripts/` — `lint.py`(검사), `metrics.py`(스타일 수치), `lineup.py`(라인업 렌더), `density_fix.py`(밀도),
  `reshade.py`(다시 칠하기), `make_detail.py`+`kitbash.py`(부품 보강). 실행은 `python -I <스킬>/scripts/…`, 현재 폴더는 프로젝트 루트.
- **blender-motion 스킬이 함께 설치돼 있어야 한다**(뼈 자세 계산 `bbpose.py`, Blender 찾기, 동작 확인 렌더). Python 3 + numpy + Pillow.
- 아트 기준 파일: 프로젝트의 `작업/모델링/기준.json`. 없으면 `templates/art_standard.json` 을 복사해 그 프로젝트의 기준 모델 수치로 고친다
  (기준 모델 = 서버에서 플레이어가 가장 자주 보는 몹. `metrics.py` 로 재서 범위를 정한다 → `references/art-standard.md`).

## 순서
1. **검사** — `lint.py <모델ID 또는 경로>[@배율] … [--theme dark]` : 오류(서버에서 깨질 것)·경고(기준 밖·겹쳐 깜박일 면·
   뒤집힌 큐브·텍스처 장수·인게임 확인 필요)·정보(큐브·렌더 뼈·키·밀도·색). 배율 = MythicMobs `model{scale=}`.
   어두운 테마 몹(엔드·공허·그림자)은 `--theme dark` (기준.json 의 `dark_theme_ranges`). 해석·성능 예산 → `references/engine-rules.md`
2. **라인업** — `lineup.py --out 작업/모델링/시험/<던전>_라인업.png --stats [--back] [--per-row 6] <기준ID=이름표> <대상…>` :
   같은 축척(1블록 = 같은 px), 마인크래프트 엔티티 조명(윗면 100%, 앞뒤 74%, 옆 50%, 아래 40%), 플레이어 키 비교,
   이름표 아래 수치. `--back` 은 뒷모습 줄 추가, `--yaw 90` 은 옆. 이름표가 없으면 모델 ID 가 붙는다.
   그림을 Read 로 열어 **무엇이 다른지 말로 적는다**: 형태(큐브 밀도·실루엣) / 픽셀 크기 / 명암·테두리 / 색.
3. **처방 고르기**
   | 증상 | 처방 | 맡는 쪽 |
   |---|---|---|
   | 픽셀이 다른 몹보다 잘거나 굵음 (px/블록 기준 밖, 소수 크기 큐브 많음) | 4단계 밀도 맞추기 | 코드 |
   | 평평하게 채운 면, 경계가 흐림, 너무 밝거나 어두움 | 5단계 다시 칠하기 | 코드 → 사람 확인 |
   | 덩어리가 단순, 실루엣이 약함 (큐브/키 기준 미달) | 6단계 부품 보강 | 코드 초안 → 사람 판정 |
   | 얼굴·문양·표면 그림 자체가 부족 | 컨셉·재질 견본은 GPT, 마감은 사람 (`references/gpt-concept.md`) | GPT·사람 |
   | 뼈 태그 충돌, 회전 규칙 밖, 2의 거듭제곱 아닌 텍스처 | 사용자에게 보고 → 인게임 확인 뒤 결정 | 사용자 |
4. **밀도 맞추기** — `density_fix.py <원본> <출력> [--scale s]` : 촘촘하면 면마다 1 px/유닛으로 다시 깔고(원래 색만 씀),
   굵으면 정수배 확대만 한다(보이는 모양 그대로 → 이어서 5단계로 1px 구조를 얹거나 사람이 다시 그림). 결과는 라인업으로 확인.
5. **다시 칠하기** — `reshade.py <원본> <출력> --val <명도> --contrast <명암 폭> [--protect #상징색,…]` :
   기본 `adjust` 는 **원래 색(색상·채도)을 두고 밝기만** 바꾼다(대비, 1px 테두리 한 칸 어둡게, 위 밝게, 가운데 살짝 밝게, 약한 얼룩).
   `--mode ramp` 는 새 색 계단으로 다시 칠해 색이 바뀔 수 있다 → 4색처럼 단조로운 텍스처에만, 렌더로 꼭 확인.
   **상징색(호박 주황, 눈빛, 보석)이 바뀌었으면 실패** → `--protect` 로 지키고 다시.
6. **부품 보강** — `templates/detail_spec_example.py` 를 `작업/모델링/설계/<모델ID>.py` 로 복사해 채우고 `make_detail.py <설계.py>`.
   - 설계 전에: 뼈 트리(부모·자식 관계), 동작 범위, 기존 큐브 좌표(`print(kit.cubes("뼈"))`), 원본 색(`print(kit.colors())`)을
     본다 → `references/detail-design.md`. 설계 변수: `SRC` `OUT` `RESHADE`(mode·protect 도) `SCALE` `THEME` `STD` `COMPARE`(ID=이름표) `LABEL` `PPB` `ANIMS`
   - **먼저 `--no-render`** (1초): 수치와 "같은 평면에 겹친 면" 경고를 본다. **겹침 0** 이 될 때까지 좌표를 고친다.
   - 그다음 렌더: 라인업 v<N>(원본·직전 판·이번 판·기준 모델, 앞·뒤 두 줄) + 동작 자세 시트(동작마다 다섯 순간, 3/4·옆) + `보고표.md`.
     사용자에게 보낼 GIF 가 필요하면 `--gif`.
   - 실루엣이 먼저다: 두건·뿔·어깨·소매·치마·무기·등불처럼 멀리서 읽히는 덩어리부터. 큐브 수 자체가 목표가 아니다.
   - PNG 를 Read 로 열어 본다(필요하면 잘라서 확대). 2~4번 고치는 것이 보통이다(설계만 고쳐 다시 실행, 판은 v1, v2 … 로 남는다).
7. **승인·보고** — 라인업 PNG·동작 확인 장면·보고표를 사용자에게 보낸다(폰에서 볼 수 있게). "수치·렌더로 확인"과 "인게임 미확인"을 나눠 적는다.
   사람이 보고 고칠 것(얼굴 픽셀, 문양)은 면 단위 목록으로 넘긴다.
8. **서버 적용**은 사용자 지시 때만: blueprints 원본 백업 → 복사본으로 교체 → `/meg reload` → (ItemsAdder) `/iazip` → 인게임 라인업 확인.

## 맡는 쪽 (조사 결론, `references/art-standard.md` 1장)
- **코드**: 잴 수 있는 일 — 검사, 밀도, 명암·테두리 규칙, 부품 큐브 배치, 라인업·동작 렌더, 보고표.
- **사람**: 실루엣·비례가 좋은지 판정, 얼굴·문양 마감, 라인업 최종 승인, 예외 승인.
- **GPT**: 정면·측면·후면 컨셉 시트, 재질 견본. 픽셀 격자·팔레트는 코드가 다시 맞춘다. 커스텀 몹 UV 텍스처를 통째로 맡기지 않는다.

## 지킬 것
- 원본 .bbmodel 은 고치지 않는다. 모든 스크립트가 출력 = 원본이면 멈춘다.
- 기존 뼈 이름·동작 이름·모델 ID 를 바꾸지 않는다(서버 설정·코드가 부를 수 있다). 태그 충돌 경고가 나도 이름 변경은 사용자 결정.
- 새 큐브는 정수 좌표(믹셀 방지), 회전은 한 축 0·±22.5·±45, **기존 뼈에 붙인다**(렌더 뼈 = 디스플레이 엔티티 수가 늘지 않고 기존 동작이 그대로 따라온다).
- 새 면이 기존 면과 같은 평면·같은 방향으로 겹치면 인게임에서 깜박인다 → `lint`·보고표의 "같은 평면에 겹친 면"을 0 으로.
- 부품 면은 원본 텍스처 빈 곳에 먼저 들어간다(장수 유지). 원본 밀도가 0.5·1·2·4 px/유닛에서 벗어나면 `density_fix` 먼저.
- 다시 칠하기·밀도 결과는 렌더로 확인한다. 수치가 기준 안이어도 보기 나쁘면 실패다.
- 코드로 그린 얼굴·문양·아이콘은 품질이 낮다고 판정된 적이 있다 → 코드는 구조 음영과 부품 형태까지, 그림은 GPT·사람.
- 인게임 확인 전에는 "완료"라고 하지 않는다.
