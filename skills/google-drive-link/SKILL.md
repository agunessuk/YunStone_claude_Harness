# 구글드라이브 연동

근거: 학원 학생관리 앱의 자료실을 "링크만" → "API 읽기 전용(서비스 계정)" → "사이트에서도 올리기(학원 계정 OAuth)"로 세 번 바꾸며 정한 것. 처음부터 마지막 형태로 가면 사용자의 클라우드 콘솔 작업을 두 번 시키지 않는다.

## 방식 고르기 (먼저 물을 것: 사이트에서 **올리기**도 하나? 계정이 **일반 Gmail**인가?)
| 방식 | 할 수 있는 것 | 맞는 경우 |
|---|---|---|
| 링크만 저장 | 사이트에 드라이브 주소를 걸어 둠 | 가장 간단, 사용자가 각자 구글 로그인 |
| 서비스 계정 + 폴더 공유(뷰어) | 사이트에서 보기·받기 | 읽기만. **일반 Gmail 드라이브에는 서비스 계정이 파일을 올릴 수 없다**(저장 공간이 없음) |
| **OAuth(학원 구글 계정 연결)** | 보기·받기·올리기·폴더 만들기·지우기(휴지통) | 일반 Gmail + 사이트에서 올리기. 기본 추천 |

## OAuth 방식 구조
- 범위: `https://www.googleapis.com/auth/drive openid email`, `access_type=offline`, `prompt=consent`.
- 구글은 http 되돌아오기 주소를 **localhost에만** 허락한다 → 되돌아오기 주소는 `http://localhost:포트/api/drive/oauth/callback`, 연결 단추는 **서버 PC에서 `http://localhost:포트`로 열었을 때만** 동작하게 막는다(내부 IP 주소로 열면 안내 문구).
- 파일: `var/google-oauth-client.json`(콘솔에서 받은 클라이언트), `var/google-oauth-token.json`(갱신 토큰). 둘 다 개인정보 폴더, 깃헙·화면·기록에 내용을 남기지 않는다.
- 앱이 **테스트 모드**(게시 안 함)면 갱신 토큰이 **7일 뒤 만료** → 7일마다 서버 PC에서 [구글 계정 연결]을 다시 누른다. 안내문·화면에 이 사실을 적는다. 게시(프로덕션)로 바꾸면 범위 `drive` 때문에 구글 검증이 필요할 수 있다.
- 사용자 단계 안내: [references/oauth-setup.md](references/oauth-setup.md)

## 자료실 화면 기본값
- 왼쪽 폴더 나무(눌러서 펼침) + 오른쪽 목록. [보기](PDF·그림·글), [받기](구글 문서는 PDF·엑셀로 바꿔 받기), [+ 새 폴더], [파일 올리기](여러 개, 끌어다 놓기, 한 파일 300MB까지), [삭제].
- 삭제는 **구글드라이브 휴지통으로**(30일 안에 드라이브에서 되살림). 폴더 삭제는 안의 것까지라고 확인창에 적는다. 맨 위 폴더는 못 지움. 같은 이름 폴더는 막음.
- 받을 때 그 파일이 자료실 맨 위 폴더 **안**에 있는지 확인한다(다른 드라이브 파일 id로 빼 가기 방지).
- 올리기·받기·지우기·연결은 접속 기록에 남긴다. 연결한 계정 이메일·설정 파일 위치는 원장에게만 보여 준다.
- 개인정보 파일(명부·성적·설치본 zip)은 자료실에 올리지 말라고 화면에 적는다. 자료실은 모든 계정이 받을 수 있다.

## 결과물을 드라이브에 올릴 때 (다른 프로젝트에서)
- 이미 연결된 앱의 토큰을 **읽어서** 쓴다. 토큰 파일을 복사하거나 다른 곳에 저장하지 않는다.
- 폴더 경로는 사용자가 말한 그대로(예: `수학과/공통수학1/자체교재/AWAKE/본문`, `…/해설지`). 없는 폴더는 만들고, 같은 이름 파일이 있으면 덮어쓸지 묻는다.
- 올린 뒤 드라이브에서 목록을 다시 읽어 파일 이름·크기를 표로 보고한다.

## 하지 않는 것
- 사용자의 구글 계정 비밀번호를 받지 않는다. 로그인·허용은 사용자가 브라우저에서 직접.
- 공유(링크 공개)를 켜지 않는다.
