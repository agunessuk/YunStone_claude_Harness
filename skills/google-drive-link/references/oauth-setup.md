# 구글 클라우드 콘솔에서 사용자가 할 일 (OAuth 클라이언트 만들기)

사용자가 화면을 보며 그대로 따라 하는 순서. 구글 화면 이름은 바뀔 수 있으니, 사용자가 보낸 화면 사진의 글자를 기준으로 다음 단계를 고른다.

## 0. 이미 해 둔 것 확인
- 사용자가 "API 사용은 이미 했다"고 하면 다시 시키지 않는다. 이미 만든 서비스 계정·뷰어 공유가 있으면 **지울 것과 남길 것**을 먼저 표로 알려 준다(서비스 계정 키는 OAuth로 바꾼 뒤에도 '연결 없을 때 보기 전용'으로 남겨 둘 수 있다).

## 1. 프로젝트와 API
- console.cloud.google.com → 프로젝트 선택(없으면 만들기) → API 및 서비스 → 라이브러리 → **Google Drive API** → 사용.

## 2. OAuth 동의 화면 (Google 인증 플랫폼)
- **브랜딩**: 앱 이름(예: 학원 자료실), 사용자 지원 이메일 = 학원 계정, 개발자 연락처 이메일. **앱 로고·앱 도메인·홈페이지·개인정보처리방침 칸은 비워 둬도 된다**(테스트 모드). 필수 표시가 없는 칸은 비운다.
- **대상(Audience)**: 사용자 유형 **외부**. 게시 상태는 **테스트**로 둔다.
- **테스트 사용자**: 학원 구글 계정(연결할 계정)을 추가. 빠뜨리면 연결할 때 "액세스 차단됨" 오류.
- **데이터 액세스(범위)**: 꼭 넣지 않아도 앱이 요청할 때 동의 화면에 뜬다. 넣는다면 `.../auth/drive`.

## 3. 클라이언트 만들기
- 클라이언트 → 클라이언트 만들기 → 애플리케이션 유형 **웹 애플리케이션**.
- 승인된 리디렉션 URI: `http://localhost:포트/api/drive/oauth/callback` (앱이 화면에 보여 주는 주소를 그대로 복사).
- 만든 뒤 **JSON 다운로드** → 서버 PC의 `var/google-oauth-client.json`으로 이름을 바꿔 넣는다.

## 4. 연결
- 서버 PC에서 `http://localhost:포트/#/drive` → [구글 계정 연결] → 학원 계정 선택.
- "Google에서 확인하지 않은 앱" 화면 → [고급] → [(앱 이름)(으)로 이동] → 드라이브 권한 허용.
- 자료실 맨 위 폴더 링크를 설정에 넣는다.

## 자주 막히는 곳
| 증상 | 원인 |
|---|---|
| `redirect_uri_mismatch` | 콘솔의 리디렉션 URI와 앱 주소가 다름(포트, 끝의 `/`, `127.0.0.1` vs `localhost`) |
| `access_denied` / 액세스 차단됨 | 테스트 사용자에 그 계정이 없음 |
| 다른 PC에서 연결 단추가 안 됨 | 정상. 서버 PC의 localhost에서만 된다 |
| 7일 뒤 자료실이 갑자기 안 됨 | 테스트 모드 갱신 토큰 만료 → 다시 연결 |
| 서비스 계정으로 올리기 실패(저장 공간 할당량) | 일반 Gmail 드라이브에는 서비스 계정이 올릴 수 없음 → OAuth로 |
| 파일을 넣었는데 사이트에 안 보임 | 맨 위 폴더 링크가 다른 폴더, 또는 서비스 계정 방식인데 그 폴더를 서비스 계정에 공유하지 않음 |
